# Team Scrum/Kanban board

A single static page (`index.html`) that talks to the `/v1/scrum/*` endpoints in this API
(`app/routers/scrum.py`). No build step, no dependencies — upload `index.html` anywhere that can
serve a static file (GitHub Pages, Netlify, Vercel, an Azure Static Web App, even a plain blob
storage container with static website hosting turned on).

## One-time setup

1. Deploy the backend changes in this commit (new `scrum_members` / `scrum_tasks` tables via the
   `0002_scrum` migration, plus the new router) to whichever environment you want the board to run
   against — right now that's `dev`, the only environment actually live.
2. Upload `index.html` to your static host of choice. No build step.
3. Open the page. If it's talking to the `dev` backend, the default API URL baked into the page
   already points there; otherwise open "API settings" on the login screen and paste the right
   backend URL (anything ending in `/v1/scrum`).
4. Click "First time setting this up? Create the admin account", enter your name, and save the
   access code it gives you — it's shown once and can't be recovered (only its hash is stored).
   That endpoint refuses itself the moment any member exists, so it only ever works once.
5. As the admin, open "Manage team" in the board header and add each teammate by name. Each add
   generates a fresh access code — send it to that person over whatever channel you'd normally
   share a password (chat, email). They paste it into the login screen; no account/email/signup
   flow needed on their end.

## How it works

- Auth is a single opaque access code per person (`X-Scrum-Code` header), checked against a sha256
  digest stored server-side — same pattern this codebase already uses for refresh tokens. There's
  no password, session or JWT involved.
- The board polls `GET /v1/scrum/tasks` every 8 seconds, so everyone's changes show up for everyone
  else without needing a websocket.
- CORS for `/v1/scrum/*` is deliberately open to any origin (see the `scrum_cors` middleware in
  `app/main.py`) since the page can be hosted anywhere — the rest of the API keeps its normal
  locked-down CORS allowlist.
- Tasks have a category (`content` / `dev` / `design` / `other`), a status column (`backlog` /
  `todo` / `in_progress` / `review` / `done`), a free-text assignee name, and an optional free-text
  sprint label. There's no formal sprint entity — the `sprint` field is just a label you type
  consistently ("Sprint 3 (Oct 6–17)") if you want tasks grouped that way later.

## Known limits (intentionally kept simple)

- Polling, not real-time push — up to an 8-second lag seeing someone else's change.
- No audit trail on task edits/deletes — this is an internal tool, not user data.
- Access codes can be regenerated by removing and re-adding a member, but there's no "reissue code"
  shortcut yet.
